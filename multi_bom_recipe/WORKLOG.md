# Multi BOM Recipe Worklog

## Scope

- Create a new addon named `multi_bom_recipe`.
- Add `master.recipe` with:
  - `name`
  - `product_id` -> `product.template`
  - `sales_channel_ids` -> `sales.config.channel`
  - `main_component_lines` -> `main.component`
- Add `main.component` with:
  - `product_id` -> `product.product`
  - `product_qty`
  - `product_uom_id` -> `uom.uom`
- Add a form view for `master.recipe` with a notebook containing two pages.

## Design Notes

- `sales.config.channel` already exists in `optp_ext` and currently points to `mrp.bom` through `bom_id`.
- To support `master.recipe.sales_channel_ids` as requested, this addon extends `sales.config.channel` with `master_recipe_id`.
- The existing `bom_id` usage is kept intact so current features are not displaced.

## Implemented Changes

- Added addon skeleton and manifest.
- Added models:
  - `master.recipe`
  - `main.component`
  - inherited `sales.config.channel`
- Added access rules for the new models.
- Added list/form/action/menu XML for `master.recipe`.
- Added company-specific recipe support with `company_id` defaulting to the current company.
- Added BoM generation/sync logic:
  - one phantom BoM per sales channel
  - generated BoMs linked back to the recipe
  - channel-specific BoM identification through `sales_channel_id`
  - merged duplicate component quantities by product
- Added automatic BoM resync on recipe and child-line create/write/unlink.
- Replaced Blink sale-order manual channel-component injection with BoM-driven procurement using the generated `Delivery` BoM only.
- Added POS channel-specific BoM selection using the POS order floor and restored standard POS move-line assignment to avoid the old quantity-rewrite workaround.
- Added early POS picking linkage so `pos_order_id` is available before move creation/explosion, allowing floor-specific BoM selection to see the correct POS context.
- Added POS invoice COGS override so anglo-saxon cost uses the actual valuation of the picking moves generated by the BoM used in the order.
